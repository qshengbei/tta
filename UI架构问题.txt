14、商品详情购买须知：若后台无 buyTips，则 WXML 中硬编码四段发饰文案，同时需与「支持7天无理由」标签以及
发布页「是否支持七天无理由退换货」并存。最终以哪条为准，需看单个商品的具体信息，不能仅凭单一界面判断。
【判断结论】三套机制：① 商品字段 supportNoReasonReturn（发布页开关，默认 false，下单快照进 order item，
order-detail 按它显示标签并过滤售后原因）——事实上的唯一真源；② 全店 settings.buyTips 纯文案；
③ WXML 硬编码兜底。矛盾：兜底首句无条件宣称“不支持七天无理由”，对 supportNoReasonReturn=true 的商品构成
前台承诺与实际售后规则冲突；且“发饰”文案在全品类展示；buyTips storage 缓存无 TTL 无失效标记，管理端改后
老用户永久看旧文案。
【当前解决】退换政策一律按单商品 supportNoReasonReturn 渲染：
- product-detail/index.wxml 删除四段发饰硬编码；购买须知首行改为政策行，true 显示“支持N天无理由退换货
（签收后N天内可申请）”绿色，false 显示“本商品不支持N天无理由退换货”灰色；其下仅在 settings.buyTips
非空时追加全店须知文案。空态口径：仅显示政策行（用户已确认）。
- 商品信息区补“支持7天无理由”绿色标签（20rpx/#52c41a，与 order-detail 商品卡完全一致），随弹窗内
selectProduct 切换商品联动（WXML 直接绑定 product.supportNoReasonReturn，无需额外 setData）。
- N 取 settings 的 afterSalesTimeConfig.noReasonReturnDays ?? noReasonReturnDays ?? 7，与 payment 页
读取口径一致。
- fetchBuyTips 缓存改为 { value, noReasonReturnDays, timestamp } 结构，TTL 30 分钟；旧的裸字符串缓存
无 timestamp 自动判废重取并覆写（用户已确认选 TTL 方案，不另设管理端刷新标记）。
- 同步删除 WXSS 孤儿类 .product-detail__notice-item，新增 .product-detail__tags/__product-tag/
__notice-policy/--yes。

15、导航栏背景色与系统主题默认色不一致时，切换 tab 会白闪。
现象：切换 tabbar 时，顶部导航栏先显示白色，再变为配置色。
原因：导航栏首帧渲染的是系统主题默认色（浅色主题即白），配置色是后套用的；
全局 window.navigationBarBackgroundColor 原为 #F5F5F5，与默认白不同，这个时间差肉眼可见。
排查过程：与 page 背景声明无关（用注释掉 background-color 做过 A/B 验证，白闪依旧）；
为 5 个 tab 页 json 显式声明同色也无效（该试验已撤销，避免与全局值冲突）。
【当前解决】将 app.json 的 window.navigationBarBackgroundColor 改为 #FFFFFF，与默认色一致，白闪消失。
副作用（已确认接受）：导航栏纯白，与页面灰底 #f5f5f5 之间出现可见分界；不要改回灰色。
